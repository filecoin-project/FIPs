# FIP-0124: Disable creation of payment channel actors

## Simple Summary

At the network upgrade, the init actor stops creating payment channel (paych) actors. Existing channels are unchanged.

## Abstract

The init actor's `Exec` method lets any caller create a multisig or paych actor. This FIP removes paych from that list, so `Exec` with the paych code CID fails with `USR_FORBIDDEN` (18). Nothing else changes: existing paych actors keep `UpdateChannelState`, `Settle` and `Collect`, no funds move, there is no state migration, and the paych actor type stays in the bundle.

## Change Motivation

Payment channels never became a meaningful part of the network. Mainnet data from [FIPs#1290](https://github.com/filecoin-project/FIPs/discussions/1290) (2026-09-16):

- 5,602 paych actors exist. All have the same state as on 2024-09-16.
- 5,555 predate the FVM (2023-03); 47 were created after it.
- Total balance is about 142.39 FIL, and total `ToSend` is about 0.000144 FIL.

A paych actor deletes itself on `Collect`, so sends to its former address can fail. [FIP-0118](./fip-0118.md) recipient handling had to account for this. New payment channels can be implemented as FEVM contracts, and paych was expected to leave the builtin actors when the FEVM was designed ([FIPs#592](https://github.com/filecoin-project/FIPs/discussions/592#discussioncomment-4722998)).

Disabling creation stops anyone new from depending on the actor and caps the set of paych actors at what exists today. It does not remove the self-deletion case for existing channels.

## Specification

In the init actor, `Exec` with a `code_cid` that resolves to the `paymentchannel` builtin type fails with `USR_FORBIDDEN` (18), regardless of caller. This is the existing `can_exec` check with `PaymentChannel` removed from the types any caller may create. `Exec` of `multisig` by any caller, and of `storageminer` by the power actor, is unchanged.

`Exec` is the only way to create a paych actor: the paych constructor accepts only the init actor as caller, and `Exec4` accepts only the EAM as caller, which creates only EVM actors.

Unchanged:

- The paych actor code, its methods and its exit codes. `UpdateChannelState`, `Settle` and `Collect` work as today on existing channels, including `Collect` deleting the actor.
- The `paymentchannel` entry in the bundle manifest and in the [FIP-0123 actor type registry](../resources/fip-0123/actor-types.md).
- All state. No migration is required.

## Design Rationale

[FIPs#1290](https://github.com/filecoin-project/FIPs/discussions/1290) proposed deleting all paych actors, crediting each channel's `ToSend` to `To` and the rest to `From`. An [objection](https://github.com/filecoin-project/FIPs/discussions/1290#discussioncomment-18458959) was that this would override outstanding vouchers and let the protocol reallocate user funds. Disabling creation stops the set of channels from growing without changing existing channels or balances. Removing existing actors would need a separate FIP.

## Backwards Compatibility

Calls to the init actor's `Exec` to create a paych actor fail after activation. This affects new-channel creation through Lotus's `PaychGet` API and `lotus paych` CLI, and calls from multisigs or EVM contracts.

Existing channels are unaffected: they can still be funded, and `UpdateChannelState`, `Settle` and `Collect` work as today.

## Test Cases

- `Exec` of the paych code CID fails with `USR_FORBIDDEN` for an account, a multisig and an EVM actor as caller, creates no actor and allocates no address.
- `Exec` of the multisig code CID succeeds for any caller, and of the miner code CID for the power actor, as today.
- `UpdateChannelState`, `Settle` and `Collect` on a paych actor created before activation behave as today, including deletion on `Collect`.

## Security Considerations

Existing channels can still delete themselves on `Collect`, so code that sends funds to arbitrary recipients must continue to handle deleted recipients.

## Incentive Considerations

None.

## Product Considerations

New payment channels can be implemented as FEVM contracts. Removing client-side paych support from nodes (for example Lotus's payment channel manager) is not a consensus change and is outside this FIP.

## Implementation

- **builtin-actors:** remove `Type::PaymentChannel` from the init actor's `can_exec` allow-list ([`actors/init/src/lib.rs`](https://github.com/filecoin-project/builtin-actors/blob/4681a100/actors/init/src/lib.rs#L181-L189)) and update tests that create paych actors through `Exec`.
- **Lotus, Forest, Venus:** ship the new actors bundle at the network upgrade. No migration.
